# ADR 0005: Ограничение частоты запросов в памяти процесса

Статус: принято (известное ограничение)
Дата: 2026-09-30

## Контекст

Правила проекта требуют ограничить частоту запросов. Развёртывание на несколько
инстансов не согласовано, а внешнее хранилище для счётчиков не подключено.

## Решение

1. **Лимит применяется по каждому клиенту**, а не по адресу: идентификатор —
   идентификатор пользователя, а для неаутентифицированных запросов — IP.
   Иначе несколько пользователей за одним корпоративным NAT делили бы один
   бюджет.

2. **Реализация — фиксированное окно в памяти процесса.** Просто, не требует
   инфраструктуры и достаточно для одного инстанса.

3. **Ответ 429 содержит `Retry-After`**, чтобы клиент знал, когда повторить.

4. **Просроченные окна удаляются**, иначе процесс накапливал бы по одной записи
   на каждого клиента.

## Известное ограничение

Счётчики не общие между инстансами, поэтому суммарный лимит при N инстансах
равен N × заданному. Перед горизонтальным масштабированием счётчики нужно
вынести в общее хранилище. Это зафиксировано здесь, чтобы ограничение не
потерялось при чтении кода.
