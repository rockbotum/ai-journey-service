# ADR 0006: Хранилище в памяти на текущем инкременте

Статус: принято (временная реализация)
Дата: 2026-09-30

## Контекст

Схема PostgreSQL спроектирована в `migrations/0001_init.sql`, но адаптер хранилища
в этом инкременте не написан.

## Решение

1. **`store.Store` — единственная точка доступа к данным.** Сервис не знает, где
   лежит бронирование, поэтому замена реализации не затрагивает бизнес-логику.

2. **`store.NewMemory` используется как полноценная реализация** контракта: она
   глубоко копирует при чтении и записи, не отдаёт наружу свои внутренние
   структуры, поддерживает оптимистическую блокировку и идемпотентность с
   отпечатком запроса.

3. **Потеря данных при перезапуске — осознанная.** Это инкремент разработки, а
   не рабочее развёртывание.

4. **Идемпотентность в памяти ведёт себя как в БД** при одном процессе, включая
   отказ при повторе ключа с другим запросом.

## Что заменяется

Адаптер PostgreSQL поверх `apply_booking_transition`. Он должен вернуть те же
ошибки (`ErrNotFound`, `ErrConflict`, `ErrIdempotencyConflict`), чтобы поведение
сервиса и API не изменилось.
