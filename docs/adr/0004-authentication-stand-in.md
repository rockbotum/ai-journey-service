# ADR 0004: Аутентификация — заменяемая заглушка

Статус: принято (временная реализация)
Дата: 2026-09-30

## Контекст

Правила проекта требуют ограничить доступ и сделать это проверяемо. Полноценный
провайдер идентичности в этом инкременте не подключён.

## Решение

1. **Анонимного доступа нет.** Каждый запрос `/v1/*` обязан нести
   `Authorization: Bearer <key>`. Бронирование принадлежит пользователю, и
   чужой не должен его прочитать.

2. **Ключи хэшируются при старте.** `auth.New` хранит только SHA-256 от ключа.
   Дамп памяти или отладочный вывод конфигурации не раскрывают рабочее
   значение. Для сравнения используется `crypto/subtle`.

3. **Ошибка не различает «нет ключа» и «неверный ключ».** Иначе эндпоинт можно
   использовать для перебора. Тело 401 одинаково и не содержит деталей.

4. **Ключ не попадает в логи.** Вместо него используется короткий необратимый
   отпечаток `auth.Fingerprint`, достаточный для корреляции.

5. **Проверка всех секретов на старте.** Пустой набор ключей, пустой ключ или
   ключ без идентификатора — ошибка конфигурации, а не повод запуститься.

6. **Единственное исключение — `/healthz`.** Оркестратор не имеет учётных
   данных; проба, отвечающая 401, привела бы к рестарту исправного сервиса.
   Проба не раскрывает сведений о зависимостях.

## Что заменяется в продакшене

`auth.Authenticator` — намеренно минимальная реализация. Её заменяет OIDC или
иной внешний поставщик идентичности. Интерфейс узкий: `Authenticate` возвращает
`Principal`, остальное не меняется. Ограничение по областям (`Scopes`) заведено
заранее, но пока не проверяется в обработчиках — при подключении реального IdP
это первое, что нужно включить.
